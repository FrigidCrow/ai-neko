# ai-neko 实施计划

日期：2026-09-25。范围依据：用户要求独立建立项目，使用 LangGraph，具体实现参考已完成的 N.E.K.O 教程与源码，并优先复用已有交互模块。

## 1. 目标、现状与交付边界

最终交付为 Windows 11 x64 上可直接启动的个人 AI 伴侣：文字/语音对话、角色表现、本地长期记忆、可控制的视觉与主动陪伴、工具扩展，以及可升级保留数据的桌面包。云模型可用于生成、摘要和事实整理；相关请求上下文会发送到配置的模型端点。

独立目录、Git 初始化、改名、计划与图解文档已完成。2026-09-25 用户授权开始第一阶段，进入 M0 实现；M1–M6 继续 Pending。本文中未在 REVIEW 留证的模块和验收阈值仍为待实现设计。原工程源码和教程能作为参考，不能作为本工程运行证据。

- 原工程：`/Users/frigidcrow/Dev/neko-companion`，只读参考，源 commit `90ccf79c95e80f899b9bf3395fa8cd9a9bfe29be`。

## 3. 项目身份与本地数据隔离

M0 已实现数据根、配置格式、后端实例锁与连接发现；以下桌面 AppUserModelID、系统凭据和显式导入规则仍属对应后续阶段。所有本轮运行使用临时合成资料，未迁入个人配置：

- 应用标识 `ai-neko`；Electron AppUserModelID 和单实例锁使用独立标识，显示名 ai-neko。
- Windows 数据根 `%LOCALAPPDATA%\ai-neko`；Mac 开发使用 `~/Library/Application Support/ai-neko`；测试强制使用临时根。统一由路径解析器提供，环境覆盖名 `AI_NEKO_DATA_DIR`。
- 目录包含 `config/`、`memory/`、`checkpoints/`、`logs/`、`backups/`、`runtime/`、`assets/`。原版 `%LOCALAPPDATA%\N.E.K.O` 和 `%APPDATA%\N.E.K.O` 不属于候选回退目录。
- 后端仅监听 loopback，端口由操作系统分配或读取本工程明确配置；桌面进程从本工程 runtime 文件获得地址和会话连接令牌。禁止扫描或接管原版端口。WebSocket 校验来源与令牌，退出清理仅匹配本工程进程。
- 模型凭据采用独立 Windows Credential Manager 入口；M0 开发仅读取显式 `AI_NEKO_MODEL_API_KEY` 环境变量，不自动加载 `.env`。适配器已选定、系统存取留 M1；持久日志、测试输出和 Git 中不写 Key。
- 云模型调用允许；记忆自动云同步、跨工程共享、原版数据自动迁移默认关闭。

计划路线与阶段验收链见 [00 路线图](DIAGRAMS.md#diagram-00-roadmap)，模块详图见 [图册](diagrams/index.html)。

## 4. 分阶段工作与验收

按 M0 → M1 → M2 → M3 → M4 → M5 → M6 推进。M1 中可使用临时测试页面，M3 再接正式角色界面；这不改变最终 Windows App 目标。具体模块与事件契约见 [ARCHITECTURE](ARCHITECTURE.md)，源码和课程入口见 [REFERENCES](REFERENCES.md)。

### M0：隔离、版本与复用接口验证

本轮执行范围（2026-09-25，先于实现登记）：

- 建立 `src/ai_neko`、独立 `.venv`、Python 3.11 patch 固定与 `uv.lock`；固定后续桌面/前端工具链建议版本，实际安装与仅选定版本分开记录。
- 实现应用身份、平台路径解析器、数据根所有权标记、专属配置/日志/备份/runtime 子目录、进程单实例锁与 loopback 端口发现；拒绝相对/非法/原版目录和冲突端口，runtime 令牌不进入日志。
- 实现只含健康检查和鉴权 WebSocket 的最小服务；HTTP/WS 使用会话令牌，WS 同时校验 Origin。首个模型协议固定为 OpenAI 兼容 Chat Completions；M0 不调用真实模型。凭据选择独立 Windows Credential Manager 入口，M0 开发仅接受显式 `AI_NEKO_MODEL_API_KEY` 环境变量，不读取其他工程或通用凭据。
- 实现两节点、条件边、自定义流式事件和 SQLite checkpoint 的合成图；提供内部线程 ID 映射和受 scope 约束的 get/history/run/resume/delete 接口。示例含显式暂停/恢复，用来验收进程重开与越界拒绝，不代表聊天或音频取消已实现。
- 只读核查桌面/音频/渲染/记忆来源、许可证及导入副作用，形成 `docs/M0-REUSE-AUDIT.md`；本阶段不需要移植生产模块，导入清单保持明确为空。原桌面壳仍无法核实时，采用本项目最小 Electron 宿主作为 M3 基线。
- 用临时合成资料完成单元与真实子进程测试；编写 Windows 11 x64 可运行的相同 smoke 入口和取证说明。Mac 已运行测试与 Windows 尚未执行项目分列，未有真机证据时 M0 总体只记 Partial。

本轮验收清单：依赖可按 lock 同步；导入本项目无写盘/启动服务；配置不泄露凭据；非法数据根/端口占用/第二实例/错误 token 或 Origin 均拒绝；同外部 thread ID 的不同用户/角色在所有五类状态入口隔离；跨真实 Python 进程恢复同一 checkpoint；关闭清理本项目 runtime 且不影响另一数据根实例；来源核查与宿主决策有据；Windows 真机项保留独立状态。

实现细节、命令与状态入口：[M0 开发运行](M0-QUICKSTART.md)、[合成图证据](m0-graph-notes.md)、[复用/版本核查](M0-REUSE-AUDIT.md)、[Windows 取证](WINDOWS-M0.md)。Node/Electron/前端目前固定候选版本并核对 engines/peer，未安装或生成产品前端 lock；不能把元数据兼容当成运行兼容。Windows 环境未取得前，M0 总体保持 Partial；M1–M6 不自动开始。

工作：固定 Python/Node/LangGraph/前端兼容版本；建立本工程锁文件；验证路径解析与 loopback 连接；选定首个模型协议；完成桌面壳、音频、渲染与记忆组件的访问/许可/导入副作用核对。只迁入后续阶段确需的模块，并记录来源。

验收：

- 记录源码基线、每个移植文件、许可证与前后差异；可单独 import 所选模块，不读取原版配置、不自动启动服务。
- 在临时目录执行最小 LangGraph：两个节点、一条条件边、流式事件和文件 checkpoint；关闭 Python 进程后重开可恢复同一线程状态。
- 切换用户/角色/会话 ID 后不存在状态混用；后端内部线程 ID 绑定用户和角色，两个角色复用同一外部 thread_id 时，get/history/run/resume/delete 均不能越界读写旧 checkpoint。非法数据根、占用端口、第二实例和错误连接令牌有明确结果。
- 明确 Electron 采用“已核实原桌面工程”还是“本项目最小宿主”；记录依据。2026-09-25 的账号访问失败不推定将来永远不可访问，也不阻止继续核实其他组件。
- 保存 Windows 11 x64 最小启动证据；Mac 实验单列。未拿到 Windows 环境时，只能完成对应源码项。

### M1：LangGraph 文字对话与工具循环

工作：实现 GraphState、节点、模型适配、消息事件和 SessionRuntime；固定人设，可配置云模型；一个合成只读工具用于验证循环。兼容 UI 事件的适配层先只覆盖文字路径。

验收：

- 真模型完成连续 10 轮文字对话；节点记录能追踪“输入 → 上下文 → 模型 → 可选工具 → 回复”，流式文字在完整生成前可见。
- 工具参数校验、错误/无结果、超时、循环上限（初始最多 3 轮工具调用）都有测试；同一次调用只有一个执行者，不再启动 N.E.K.O 的完整工具循环。
- 网络中断与认证失败显示明确错误；取消后不把迟到文字附到新一轮。图内部摘要/记忆提取的文本不能混入用户可见回复。
- 在对话提交前、提交中、提交后分别取消：Runtime 负责正常/部分回合的幂等结算，即使图末节点未运行也不丢失已接受输入和有证据的已投递内容；强制结束进程后可恢复待结算记录，不重复追加或覆盖新回合。
- 数据库落盘后退出并重开可接续原会话；新会话使用新 thread_id。模型 API 测试与 fake 模型测试分别记录。

### M2：跨会话记忆与可纠正、可遗忘

工作：提取 N.E.K.O 近期记录、原文日志、事实及检索的必要实现，由 MemoryServiceAdapter 接入图；按需逐步接入反思/人格处理。原始证据、事实状态、来源、用户/角色范围和整理任务统一管理；图 checkpoint 不成为第二份事实权威。

验收：

- 固定合成用例记录 5 个偏好和 5 个事件；检查本地落盘内容。正常退出及重启电脑后，使用新 thread_id 提问，10 项均能检索到对应来源；真实模型回答逐项核对，错误不能计为通过。
- 同时测试 5 个未提供的信息，回复应表达未知；角色 A 的私有事实不能被角色 B 的查询命中。
- 先记录“喜欢无糖咖啡”，再改为“现在喜欢茶”；检索以有效新事实为准，保留纠正来源。删除测试覆盖事实、原文、派生内容、索引、旧 checkpoint 中的记忆副本和未完成整理任务。
- 以记忆版本/删除标记阻止迟到提取与旧 checkpoint 恢复后把已删信息重新写回；备份中的旧内容只在明确恢复时可出现，恢复过程也应用删除策略。
- 中途强制结束进程后，后台记忆任务可重试；使用稳定 source_id/turn_id/job_id 去重，不重复生成同一条事实。
- 提供基本查看、纠正和删除入口；文件保存、检索命中、请求注入、模型正确使用四步分别留证。

### M3：Windows 桌面、角色与前端复用

工作：按 M0 决策接入桌面宿主，提取 N.E.K.O 聊天/设置页面及一个有可用许可的角色渲染路径（首选 Live2D 或现有易接入路径，其他格式后续扩展）；接通文字、情绪、口型所需事件。先使用可分发测试素材。

验收：

- Windows 上由桌面入口启动后端和界面，关闭/托盘退出后无本项目残留服务；原版同时运行不受影响。
- 窗口、托盘、角色显示、拖拽、透明区域和点击穿透分别实测；DPI 100%/150%、双显示器及中文路径有记录。
- 跨窗口重连/角色切换不串用记忆或旧轮输出；已有前端对 N.E.K.O API 的每个使用点在适配表中有对应，不宣称整套 UI 无改动接入。
- 这是开发桌面集成通过，最终无开发工具的便携发行验收仍属于 M6。

### M4：语音输入、输出与插话打断

工作：优先提取 N.E.K.O 麦克风采集、VAD/ASR、TTS、播放器和口型联动；首版采用 ASR → LangGraph 文本决策 → TTS 的路径。原生实时音频模型另列扩展，避免一开始同时维护两套语音决策。

验收：

- Windows 真机完成录音、识别、回复、发声与口型；拒绝/撤销麦克风访问、设备切换、断网和播放器结束事件均有记录。
- 同一 turn_id 贯穿图、TTS、播放器；收到取消事件后先停播放/清旧队列，再取消生成，拒收过期片段。
- 初始目标：应用收到取消事件到旧音频停止，20 次测量 p95 不超过 300ms；用户开口到取消事件的识别延迟另测，不混在一起隐藏。该阈值是待验收目标，尚无性能结果。
- 用户连续插话、旧请求晚返回、关闭窗口时仍有 TTS 任务等案例，不出现旧内容复播或写成新回合。
- 对话提交前/中/后插话时，核对实际播放位置与记忆结算；只发送尚未播放的语音不算用户已听到，取消路径复用 M1 的持久收尾机制。

### M5：视觉、主动陪伴与实际工具

工作：复用 N.E.K.O 的图像输入处理、活动门控和主动触发思路，统一进入同一个图；接入至少两个实际只读工具，再逐步添加需要外部副作用的工具。视觉来源与启停在界面明确。

验收：

- 图像绑定当前轮次，旧截图/旧模型结果不能进入新轮；关闭视觉后不再采集或发送新图像。
- 主动行为遵守静音、忙碌、冷却和用户输入优先；后台触发只能排入同一会话调度入口，不能另开完整聊天系统。
- 两个只读工具各有成功、失败和无命中证据。将来新增写文件/发消息等副作用时，在已有授权范围内执行，并用持久操作记录防重放；checkpoint 不保证外部动作自动恰好一次。
- 用户可看见触发原因与开关；退出后不残留定时器、采集或后台生成。

### M6：Windows 分发、升级与长期运行验证

工作：构建独立 Windows 便携 ZIP，包含桌面宿主、后端及必要资源；实现配置/记忆迁移、备份恢复与检查点保留策略。原版 Steam 更新/云存档不直接接入本产品。

验收：

- 干净 Windows 11 x64 上解压双击启动，不需用户另装 Python、Node、uv 或打开终端；记录源码 commit、锁文件、runner/系统环境、产物 SHA256。
- 中文用户名/路径、端口冲突、第二实例、安装在不可写程序目录、退出清理均通过；所有运行数据写入本工程数据根。
- 从旧测试版升级后保留有效记忆和凭据入口；损坏配置可诊断；备份实际恢复并保持删除策略，不仅检查“生成了 ZIP”。
- 连续 7 天受控日常使用，覆盖文字、语音、主动事件；记录至少 20 次退出/重开及内存、数据库增长和失败日志。此项只支持这一观察窗口，不宣称无限期稳定。
- REVIEW 中每个 P0/M0–M6 验收项有证据或明确未完成；存在必要功能 Failed/Pending 时不发布“完整可用”结论。
