日期：2026-09-25。范围依据：用户要求独立建立项目，使用 LangGraph，具体实现参考已完成的 N.E.K.O 教程与源码，并优先复用已有交互模块。

## 1. 目标、现状与交付边界

最终交付为 Windows 11 x64 上以可见猫娘桌宠为主体的个人 AI 伴侣：文字/语音对话、联网查攻略与资料、角色表现、本地长期记忆、可控制的视觉与主动陪伴，以及可升级保留数据的桌面包。云模型可用于生成、摘要和事实整理；相关请求上下文会发送到配置的模型端点。

2026-09-25 用户明确调整优先级：**查攻略/搜索资料是首版核心需求，提前到 M1；键鼠自动操作和电脑控制当前不做。** 当前不接入代点击、代输入、接管游戏/其他软件、浏览器账号操作或通用系统命令工具。用户手动拖拽桌宠、点击本应用界面、语音输入与主动提供截图仍保留；查询攻略不依赖这些后续交互完成。

**当前产品定义（用户最新指令）**：M1 重定义为 **MVP1 可见猫娘桌宠最小闭环**：桌面猫娘 → 文字输入 → 真正的流式气泡/伴随回复 → 停止/继续聊天/查攻略 → 本地会话恢复。基础桌面、单角色渲染与基本托盘从 M3 提前到 M1，不依赖 M2 长期记忆。完整范围、关卡与验收以 [MVP1 桌宠规格](MVP1-DESKTOP-PET.md) 为准。已发布 `v0.3.0-alpha.1` 桌宠工程预览，Windows 11 真机及真实服务完整验收仍待。

| 项目 | 本计划采用的方向 | 代价或待验证项 |

| 依赖和资源 | 本工程独立 `.venv`、前端依赖、模型资源及锁文件 | 不共享原工程安装目录，不默认下载全部模型和素材 |

## 3. 项目身份与本地数据隔离

M0 已实现数据根、配置格式、后端实例锁与连接发现；网页预览已有 Windows 系统凭据实现，桌面 AppUserModelID/桌面实例锁待 M1 桌宠关卡实施。显式导入仍属后续阶段。已记录测试使用临时合成资料，未迁入个人配置：

- 应用标识 `ai-neko`；Electron AppUserModelID 和单实例锁使用独立标识，显示名 ai-neko。
- Windows 数据根 `%LOCALAPPDATA%\ai-neko`；Mac 开发使用 `~/Library/Application Support/ai-neko`；测试强制使用临时根。统一由路径解析器提供，环境覆盖名 `AI_NEKO_DATA_DIR`。
- 目录包含 `config/`、`memory/`、`checkpoints/`、`logs/`、`backups/`、`runtime/`、`assets/`。原版 `%LOCALAPPDATA%\N.E.K.O` 和 `%APPDATA%\N.E.K.O` 不属于候选回退目录。
- 后端仅监听 loopback，端口由操作系统分配或读取本工程明确配置；桌面进程从本工程 runtime 文件获得地址和会话连接令牌。禁止扫描或接管原版端口。WebSocket 校验来源与令牌，退出清理仅匹配本工程进程。
- 模型凭据采用独立 Windows Credential Manager 入口；M0 开发仅读取显式 `AI_NEKO_MODEL_API_KEY` 环境变量，不自动加载 `.env`。M1 网页预览已实现 Windows 系统存取并有 CI 证据；持久日志、测试输出和 Git 中不写 Key。
- 云模型调用允许；记忆自动云同步、跨工程共享、原版数据自动迁移默认关闭。

计划路线与阶段验收链见 [00 路线图](DIAGRAMS.md#diagram-00-roadmap)，模块详图见 [图册](diagrams/index.html)。

### M0：隔离、版本与复用接口验证

本轮执行范围（2026-09-25，先于实现登记）：

- 建立 `src/ai_neko`、独立 `.venv`、Python 3.11 patch 固定与 `uv.lock`；固定后续桌面/前端工具链建议版本，实际安装与仅选定版本分开记录。
- 实现应用身份、平台路径解析器、数据根所有权标记、专属配置/日志/备份/runtime 子目录、进程单实例锁与 loopback 端口发现；拒绝相对/非法/原版目录和冲突端口，runtime 令牌不进入日志。
- 实现只含健康检查和鉴权 WebSocket 的最小服务；HTTP/WS 使用会话令牌，WS 同时校验 Origin。首个模型协议固定为 OpenAI 兼容 Chat Completions；M0 不调用真实模型。凭据选择独立 Windows Credential Manager 入口，M0 开发仅接受显式 `AI_NEKO_MODEL_API_KEY` 环境变量，不读取其他工程或通用凭据。
- 实现两节点、条件边、自定义流式事件和 SQLite checkpoint 的合成图；提供内部线程 ID 映射和受 scope 约束的 get/history/run/resume/delete 接口。示例含显式暂停/恢复，用来验收进程重开与越界拒绝，不代表聊天或音频取消已实现。
- 只读核查桌面/音频/渲染/记忆来源、许可证及导入副作用，形成 `docs/M0-REUSE-AUDIT.md`；本阶段不需要移植生产模块，导入清单保持明确为空。原桌面壳仍无法核实时，采用本项目最小 Electron 宿主；现按用户最新指令在 M1 桌宠闭环实施。
- 用临时合成资料完成单元与真实子进程测试；编写 Windows 11 x64 可运行的相同 smoke 入口和取证说明。Mac 已运行测试与 Windows 尚未执行项目分列，未有真机证据时 M0 总体只记 Partial。

本轮验收清单：依赖可按 lock 同步；导入本项目无写盘/启动服务；配置不泄露凭据；非法数据根/端口占用/第二实例/错误 token 或 Origin 均拒绝；同外部 thread ID 的不同用户/角色在所有五类状态入口隔离；跨真实 Python 进程恢复同一 checkpoint；关闭清理本项目 runtime 且不影响另一数据根实例；来源核查与宿主决策有据；Windows 真机项保留独立状态。

实现细节、命令与状态入口：[M0 开发运行](M0-QUICKSTART.md)、[合成图证据](m0-graph-notes.md)、[复用/版本核查](M0-REUSE-AUDIT.md)、[Windows 取证](WINDOWS-M0.md)。Node/Electron/角色渲染目前仅固定候选版本并核对 engines/peer，现前移到 M1 实装；已发布网页工程预览没有 Node 前端依赖或构建步骤，浏览器与冻结包中的静态文件组合证据不能替代桌宠验证。Windows 11 真机证据取得前，M0 总体保持 Partial；本轮用户已另行授权 M1，见第 12 节，M2–M6 不自动开始。

### M1 / MVP1：可见猫娘桌宠、流式文字与查攻略

工作：实现 GraphState、节点、模型适配、消息事件和 SessionRuntime；固定人设，可配置云模型。先用合成只读工具验证循环，再接入首版必需的 `search_web`（搜索公开资料）和 `read_web_page`（读取公开网页正文），完成问题→搜索→读正文→整理攻略并附来源。基础宿主、单猫娘渲染与伴随输入/气泡属于本阶段必需项；聊天、设置和攻略期间角色可见，收起面板后保留桌宠，语音后置。网页可用于开发调试，不能作为 MVP1 产品验收入口。查询服务与模型端点分别配置，供应商/鉴权/费用在接入时明确，不假定模型 API 自带联网能力。

验收：

- 先完成 [MVP1 规格](MVP1-DESKTOP-PET.md) 的 A 猫娘显示关卡，再完成 B 对话、C 持续使用、D 下载包。默认角色已确定为用户确认的白裙 YUI Lolita，来源与适用许可见 [资源说明](MVP1-ASSETS.md)；Windows 透明无边框显示、基本待机、拖拽/缩放/置顶、托盘找回、位置恢复与退出清理是必要验收项。
- 点击猫娘展开文字输入；短回复气泡和长文面板围绕角色，关闭聊天后角色仍可见。收到真实增量即显示，停止/失败/重试不串轮；猫娘状态来自同一回合事件，不能另建决策循环。
- 真模型完成连续 10 轮文字对话；节点记录能追踪“输入 → 上下文 → 模型 → 可选工具 → 回复”，流式文字在完整生成前可见。
- 工具参数校验、错误/无结果、超时、循环上限（初始最多 3 轮工具调用）都有测试；同一次调用只有一个执行者，不再启动 N.E.K.O 的完整工具循环。
- 查攻略回答给出可执行步骤和可点击来源，关键事实能对应实际读取的正文片段。涉及游戏/软件版本、平台或其他影响结果的条件时先从上下文识别，缺少关键条件再询问；来源未给日期/版本则记未知，抓取时间不冒充内容更新时间。
- 区分搜索摘要、已读取正文和无法读取的页面；登录墙、不可访问、正文提取失败、无命中或来源冲突有明确结果，不能把标题/摘要当作已读全文，也不能编造来源或“最新攻略”。结果不足时说明缺口，仍可提供标注为未联网核实的已有知识。
- 至少 5 组固定合成需求覆盖正常步骤、版本不明、资料冲突、无命中、正文不可读；另测试超时/限流/鉴权失败、恶意网页指令和取消后的迟到结果。至少 3 次真实联网查询完成搜索→正文→带来源回答，单列查询、提供方/模型、读取片段、来源链接和逐项人工核对；fixture 通过不能冒称真实联网通过。
- 工具仅允许公开 HTTP(S) 搜索/正文读取，限制请求次数、大小和时长，拒绝本机/内网/文件协议并重新校验重定向目标；不使用个人浏览器配置或 Cookie，不把整段私有记忆自动提交给搜索方。网页文本作为资料，不能授予新工具权限；运行注册表不包含键鼠/电脑控制工具。
- 网络中断与认证失败显示明确错误；取消后不把迟到文字附到新一轮。图内部摘要/记忆提取的文本不能混入用户可见回复。
- 在对话提交前、提交中、提交后分别取消：Runtime 负责正常/部分回合的幂等结算，即使图末节点未运行也不丢失已接受输入和有证据的已投递内容；强制结束进程后可恢复待结算记录，不重复追加或覆盖新回合。
- 数据库落盘后退出并重开可接续原会话；新会话使用新 thread_id。模型 API 测试与 fake 模型测试分别记录。
- 通过 GitHub Releases 下载 Windows x64 桌宠 ZIP，解压双击后首先出现猫娘；包含宿主、后端、默认角色与依赖，不需另装 Python/Node/uv，不以浏览器或终端作主入口。设置从猫娘/托盘进入；完成规格 V01–V09，Windows CI 与 Windows 11 真机分开记录。MVP1 暂无语音和长期事实记忆；旧网页 alpha.1 与源码启动不能代替桌宠下载包验收。

### M2：跨会话记忆与可纠正、可遗忘

工作：提取 N.E.K.O 近期记录、原文日志、事实及检索的必要实现，由 MemoryServiceAdapter 接入图；按需逐步接入反思/人格处理。原始证据、事实状态、来源、用户/角色范围和整理任务统一管理；图 checkpoint 不成为第二份事实权威。

验收：

- 固定合成用例记录 5 个偏好和 5 个事件；检查本地落盘内容。正常退出及重启电脑后，使用新 thread_id 提问，10 项均能检索到对应来源；真实模型回答逐项核对，错误不能计为通过。
- 同时测试 5 个未提供的信息，回复应表达未知；角色 A 的私有事实不能被角色 B 的查询命中。
- 先记录“喜欢无糖咖啡”，再改为“现在喜欢茶”；检索以有效新事实为准，保留纠正来源。删除测试覆盖事实、原文、派生内容、索引、旧 checkpoint 中的记忆副本和未完成整理任务。
- 以记忆版本/删除标记阻止迟到提取与旧 checkpoint 恢复后把已删信息重新写回；备份中的旧内容只在明确恢复时可出现，恢复过程也应用删除策略。
- 中途强制结束进程后，后台记忆任务可重试；使用稳定 source_id/turn_id/job_id 去重，不重复生成同一条事实。
- 提供基本查看、纠正和删除入口；文件保存、检索命中、请求注入、模型正确使用四步分别留证。

### M3：角色表现扩展与多角色

基础宿主、单猫娘、伴随对话与基本托盘已经前移为 M1/MVP1 必需项。M3 在该基础上扩展角色表情/动作、角色切换及确有需求的其他格式；继续按来源和许可逐项提取可复用渲染组件，不重复建设聊天循环。

验收：

- 新动作/渲染路径仍保持当前回合归属，不因切换角色播放旧轮状态。
